# SC-WER C2/C3 — przygotowanie Preview

Kod jest domyślnie wyłączony. Aktywacja dotyczy wyłącznie projektu Preview po niezależnym review SQL/uprawnień i zielonych natywnych testach. Nie wysyłamy zaproszeń do rzeczywistych kandydatów.

1. Zastosować zrecenzowane C1, następnie `20261106065733_sc_wer_broker_limiter.sql` i `20261106070123_sc_wer_staff_access.sql` wyłącznie w Preview.
2. Wykorzystać istniejącą procedurę dedykowanego loginu `competency_gateway_*`: NOINHERIT, NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOREPLICATION, NOBYPASSRLS; jedyne członkostwo `competency_test_gateway` z SET, bez ADMIN i INHERIT. Login nie jest właścicielem żadnego obiektu, nie ma bezpośredniego dostępu do tabel ani roli authenticated/service_role. Wymagany zaufany TLS i wyłączone logowanie parametrów SQL zgodnie z istniejącym audytem B3.
3. Ustawić tylko Preview: `COMPETENCY_BROKER_LIMITER=postgres`, dokładny HTTPS `COMPETENCY_BROKER_ORIGIN`, dedykowany DSN i dwa niezależne losowe klucze 32-bajtowe (hex) pod nazwami z `.env.example`. Dopiero po sprawdzeniu konfiguracji włączyć `COMPETENCY_BROKER_ENABLED` i `COMPETENCY_CANDIDATE_PREVIEW`. Wartości nie trafiają do repo, logów ani raportu.
4. Wykonać syntetyczny smoke: aktywna shortlista → wersja zadania → wydanie linku → kandydat start/szkic/submit → ocena rekrutera dokładnymi cytatami → raport z rozdzieleniem dowodów, deklaracji i braków. Sprawdzić obcą firmę, viewer, rotację, usunięcie shortlisty i wycofanie.

Gateway używa bezpośredniego hosta `db.orbyscrupgnupifzlqxp.supabase.co:5432`, bazy `postgres` i dokładnego loginu `competency_gateway_*` (bez sufiksu projektu używanego przez pooler). DSN nie może zawierać parametrów query. Dla bezpośrednich hostów Supabase runtime używa tych samych dwóch oficjalnych CA co istniejący adapter płatności Preview; sprawdzanie łańcucha oraz nazwy hosta pozostaje włączone. Nie trzeba i nie wolno wyłączać weryfikacji TLS. Pozostałe hosty, w tym jednorazowe bazy CI, korzystają ze standardowego zaufania Node. `COMPETENCY_BROKER_ORIGIN` należy ustawić na dokładny HTTPS alias Preview używany w linkach do kandydata. Inne aliasy i URL-e wdrożeń nie przechodzą sprawdzenia origin; nie ma wildcard ani automatycznego zaufania nagłówkowi Host.

Limiter używa istniejącej bazy, bez dodatkowej usługi. `competency_runtime.rate_window` jest odrębną powierzchnią techniczną: jeden wiersz, maksymalnie 300 liczników HMAC źródeł, bez IP, tokenów, identyfikatorów kandydatów i treści odpowiedzi. Limity: 15 żądań na źródło oraz 300 globalnie na 60 sekund. Czas pochodzi z bazy; aktualizacja jest chroniona blokadą wiersza. Po upływie okna liczniki nie mają ważności i są zastępowane przez następne żądanie. Przy całkowitym braku ruchu fizyczny wiersz może pozostać — nie deklarujemy automatycznego czyszczenia po 75 sekundach jak dla Redis. Nie jest adapterem danych kandydata i nie zmienia sygnatury R12.

Runtime wymaga jawnego wyboru `postgres` lub `redis`. W trybie postgres audyt gateway dopuszcza dokładnie dodatkową funkcję `private.consume_competency_rate_limit(text,bigint)`; nadal zabrania dostępu do tabel. Awaria limitera zamyka obsługę błędem ogólnym. Redis pozostaje możliwy po osobnym uzgodnieniu usługi.

Rekruter widzi sekret raz, w kontrolce do skopiowania. Link używa fragmentu `#grant=`, który istniejąca strona B4 natychmiast usuwa z historii; token nie jest parametrem query ani trasą HTTP. Serwer nie odczytuje wcześniej wydanego sekretu, nie loguje go i nie umieszcza w rewalidowanej ścieżce. Po odświeżeniu konieczna jest rotacja, jeśli link został utracony. Każda akcja ponownie sprawdza rolę i kontekst firmy/rekrutacji/aplikacji; SQL egzekwuje R1 niezależnie od UI.

Każda potwierdzona operacja w formularzu dostaje nowy klucz następnego żądania. Przy utracie odpowiedzi zachowane są klucz i oczekiwana rewizja poprzedniej operacji, także po odświeżeniu statusu bez przeładowania strony. Ponowienie odczytuje zapisany rezultat i nie obraca linku ponownie. Stary podgląd znika przy rozpoczęciu kolejnej operacji; niepewna odpowiedź nie pozostawia go jako aktualnego.

Oceny testu pozostają w tabelach competency. Nie są ocenami AC ani raportem preselekcji. Brak cytatu oznacza brak danych. Pokrycie poniżej 60% nie daje wyniku zbiorczego. Raport nie podejmuje decyzji zatrudnieniowej.

Lokalna weryfikacja: pełny replay i 13 testów C1/C2/C3 na PostgreSQL 17.5/PGlite, w tym Chromium → rzeczywisty dokument B4 → broker → SQL → ocena człowieka → parser raportu: PASS. Typecheck i build: PASS. Natywne macierze PG16/17 oraz rzeczywisty eksport trasy Next z dedykowanym loginem i zaufanym TLS są osobnymi obowiązkowymi testami CI. Lokalny test przeglądarki nie jest dowodem aktywacji środowiska Preview.
